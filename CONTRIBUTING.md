# Contributing

Use Node 22.12+ and pnpm 11.24.0. Run `pnpm install --frozen-lockfile`, then `pnpm dev`. Keep `pnpm-lock.yaml` in version control. Dependencies are pinned to exact versions; update them deliberately and verify with `pnpm check:full`.

Before submitting a change, run `pnpm fix` and `pnpm check`. `pnpm install` points Git at `.githooks`, whose pre-commit hook runs `pnpm check`, `pnpm test:package` and the browser suite, so a commit fails if any check fails or coverage drops below a floor in `vite.config.ts`. Once they pass, it redraws the README's version, test and coverage chips from those runs (`pnpm docs:chips`) and adds them to the commit. It takes a few minutes and checks the working tree; `git commit --no-verify` skips it once. Run `pnpm test:package` for public API, packaging or stylesheet changes. For UI, lifecycle, recording and adapter changes, install the Playwright browsers and run `pnpm build` followed by the relevant `pnpm test:e2e` cases. Browser tests run against the development server's review pages, and `e2e/package.spec.ts` checks the built package with no dev server involved. `e2e/accuracy.spec.ts` runs a scene doing real CPU and canvas work and checks jank.js against the scene's own clock in every browser, with allowances in clock ticks: intervals exactly match the host's frames, carried scope time is neither lost nor counted twice, and planted sorts show in full. Run `pnpm docs:captures` to retake the images in `docs/readme` when a change alters what they show. The full release gate is `pnpm check:full`. Each CI run's summary page shows test results, coverage, package sizes, and browser results per engine (`scripts/ci/summary.mjs`).

Consumers install no runtime dependencies. Preact is bundled into the panel and viewer, and `scripts/verify-boundary.mjs` keeps the core and adapters free of it. Framework-specific adapters must remain optional.

Package JavaScript is minified with Vite's Oxc minifier, including internal identifier mangling. See [the architecture notes](docs/architecture.md) for how the panel and viewer behave. Public exports and property names remain stable. Vite preserves the annotations and whitespace needed for tree shaking in ES library builds; consuming applications can compact the final bundle further. Source maps remain available for debugging. The offline viewer is also minified. This makes distributed code smaller and less readable, but does not hide the source or provide code protection.

For npm release preparation, use `pnpm release:prepare` from a clean checkout. It runs the full release gate and writes a tarball to `artifacts/npm` without publishing. Maintainers should follow [the npm publishing guide](https://github.com/zackabrah/jank.js/blob/main/docs/publishing.md) for first-publish setup and the manual release workflow.

Use labelled fields, selectors and buttons for authoring controls. JSON is an export format, not an authoring interface. Preserve keyboard operation, scoped styles, cleanup and unavailable measurements. Don't claim GPU timings based on CPU submission durations.

When the panel or viewer changes how it looks, run `pnpm docs:captures` to retake the README's images, and review them before committing. It isn't part of the pre-commit hook: real measurements differ every run, so each retake adds about 1.5 MB to the repository's history. The hook reminds you when a UI file changes.

Tests should exercise behavioral risks: lifecycle, delayed GPU samples, recording boundaries, overlapping work and package consumers. Say in a comment above each test what behavior it checks and why that matters. Property-based tests (`*.fuzz.test.ts`, using fast-check) throw random and hostile input at the recording parser and the monitor. When one fails, fast-check prints the smallest input that still reproduces it. `pnpm check` enforces the coverage floors in `vite.config.ts`; raise them when coverage improves. Keep commits focused and verified. Include the problem, behavior change and checks in a pull request; do not publish packages or deploy a site as part of an ordinary code change.

Write commit messages as [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/). After staging, `pnpm commit` composes one with commitizen; confirming a breaking change there adds `!` to the header. Each merged PR receives one version bump from its title, description and commit messages: a breaking change is major, `feat` is minor and anything else is a patch. See [the versioning guide](https://github.com/zackabrah/jank.js/blob/main/docs/versioning.md).

Report bugs with browser/OS, reproduction steps, expected and actual behavior, and an optional recording stripped of private application labels or values. The library has no telemetry. New public API behavior and recording-format changes belong in CHANGELOG.md and docs.

Everyone taking part is expected to follow the [code of conduct](CODE_OF_CONDUCT.md). Report security issues privately as described in [SECURITY.md](SECURITY.md), not in a public issue.
